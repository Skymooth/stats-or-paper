# 开题 / 选题论证报告模板（4 部分紧凑结构）

> **用途**：开题、选题论证、给导师或评审过目。
> **结构约定**：只写四部分 + 参考文献。不要拆出"论文逻辑链""待验证项""创新点"等独立章节——这些内容并入第二部分与第四部分。
> **证据标记**：沿用 `SKILL.md` 的五状态标记 `[正式]/[预印]/[自算]/[推断]/[待核]`。全文不出现无标记的数字。
> **篇幅参考**：约 5–6 页。第一部分 1 页，第二部分 0.5 页，第三部分 2 页，第四部分 2 页。

---

## 一、背景与需求（约 1 页）

### 1.1 问题从哪来

- 用**一个具体场景**开头，不要用"随着…的发展"这类空话。
- 给出**可核查的数字或事实**，标 `[正式]` 或 `[自算]` 并附出处。

### 1.2 现有做法为什么不够

- 不是"效果不好"，而是**技术上为什么必然不够**。
- 每条局限都要能追溯到一篇文献，或一个已观察到的事实。

### 1.3 核心矛盾（一句话）

> 用一句话写出"不能同时满足的两个要求"。这句话决定整篇报告的骨架。

**自检**：这句话里的两个要求，各自都有文献在单独优化它吗？如果一个都没有，那不是矛盾，是你的猜测。

---

## 二、研究目的（约 0.5 页）

### 2.1 要产出什么

```
输入：……
输出：……
并给出：……（可证明的性质 / 可量化的保证 / 可复现的流程）
```

### 2.2 三个研究问题（RQ）

| RQ | 问什么 | 对应哪条空白 |
|---|---|---|
| RQ1 | | |
| RQ2 | | |
| RQ3 | | |

**要求**：三个 RQ 必须**成链**（RQ1 给出对象，RQ2 给出机制，RQ3 给出决策或应用），不能是三个平行话题。

### 2.3 预期贡献（3 条，每条一句话）

1.
2.
3.

**自检**：每条贡献都能映射到第三部分的某条"空白"，也能映射到第四部分的某个方案。映射不上的，删。

---

## 三、相关研究（约 2 页，本报告最重的部分）

### 3.1 按流派分组（不是按时间流水账）

每个流派写三件事：**核心思想**（一句话）→ **代表工作**（2–3 篇，带证据标记）→ **局限**（要能对应到你的 RQ）。

```
### 流派一：……

核心思想：……

| 工作 | 出处 / 状态 | 做了什么 | 局限 |
|---|---|---|---|
| | | | |

小结：这一派的共同问题是……
```

### 3.2 差距矩阵（必写）

| 工作 | 正式/预印 | 做了什么 | 没做什么 | 我们补什么 |
|---|---|---|---|---|
| | | | | |

**自检**：最后一列每一行，都要在 2.3 的贡献里找到对应项。找不到 = 删掉这一行。

### 3.3 检索方法与覆盖范围（必写，防被质疑漏读）

```
检索词：……（列 4–6 个，覆盖不同词系）
检索库：arXiv / DBLP / PMLR / ACL Anthology / CrossRef / Google Scholar
时间范围：……
覆盖限制：……（诚实写：哪些社区、哪些语言没覆盖）
```

**教训**：同一个概念在不同社区叫法完全不同。只用一个词系检索，会漏掉最危险的竞争工作。

## 四、拟解决方案（约 2 页）

### 4.1 总体思路

- 一张框图或一段流程：输入 → 处理 → 输出。
- 说清**每一步为什么这么做**，而不是"我们采用了 X 方法"。

### 4.2 按 RQ 展开

```
RQ1 怎么做：
  方法：
  关键难点：
  怎么验证：

RQ2 怎么做：
  ……
```

### 4.3 与现有工作的本质差异

> 用一段话回答："如果把我们的方法拆开，最核心的那一点新东西是什么？"

**格式**：`现有工作做 A；我们做 B；B 之所以可行，是因为 C；C 有 D 作为支撑（附证据）。`

### 4.4 可行性与风险

| 风险 | 概率 | 预案 |
|---|---|---|
| | 高 / 中 / 低 | |
| | | |

## 参考文献

按正式 / 预印分开列。每一条都必须能点开。

**正式发表**

1. 作者. (年). 标题. *出处*, 卷(期), 页. DOI.

**预印本（不作依据，仅备案）**
