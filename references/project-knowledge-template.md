# 项目知识底稿（模板）

> **这是模板，不是内容。** 复制一份到你的项目里，改成 `project-knowledge.md`（已在 `.gitignore` 中排除，不会进仓库），然后逐项填写。
>
> **为什么要它**：一份 3 万字的手稿，最常见的硬伤不是论证错，是**口径漂移**——同一个概念在引言里叫 A、方法里叫 B、实验里叫 C；同一个数字在摘要、正文、表里三个值；把别人明确没做的事说成做了。这份底稿把口径钉死，是写任何一节之前的第一个动作。

---

## 使用规则

1. 标 `[核实]` 的可直接写进论文；标 `[待核]` 的**不许写进论文**，先核实。
2. 每个数字必须带：**值 + 不确定度或区间 + 样本量 + 证据标记**。
3. 本文件只在项目内部使用；论文里出现的每个数，都能在这里找到它的来源。
4. 数字更新时只改这里，然后全文搜旧值替换——**不要在各处复制数字**。

## 三、竞争对手边界（写相关工作必须准确）

| 工作 | 状态 | 覆盖了什么 | **明确没做什么** | 我们的差别 |
|---|---|---|---|---|
| | | | | |
| | | | | |

**填写要点**

- "状态"列写 `正式（会议/期刊 + 年份）` 或 `预印（arXiv 编号 + 日期）`。
- "明确没做什么"必须来自**他们自己**的表述（局限段、future work、正文声明），不是你推测的。
- 每行的"我们的差别"要能落到你贡献列表里的一条；落不到的，那行是凑数。

**引用注意**（会反复踩）

- PMLR / OpenReview / TMLR / ACL Anthology **多数不发 DOI**——引 proceedings 页，不要硬编 DOI。
- arXiv 的 `10.48550/arXiv.xxxx` 是**预印本 DOI**，不等于正式版。
- 会议年份与 arXiv 年份经常不同，写正式版时以 proceedings 为准。

## 五、常见坑（保留这段，按项目追加）

- **AI 生成的文献**：单作者、零引用、大标题、满篇定理的 Zenodo 预印本，先怀疑。引用时仍需提及（否则审稿人会问"你没看到这篇？"），但降低其证据权重。
- **仓库星数不等于质量**，也不等于安全。
- **"疑似 AI 文献"要标出来**：在底稿里标 `[存疑]`，写论文时据此决定是否降级引用。
- **术语在跨社区时有多个名字**：查重时必须用多个词系（见 `evidence.md` §五），否则会漏掉最危险的竞争工作。
