# 选题：十个透镜与七个认知框架

卡住的时候不要硬想，按流程走一遍。这一份分三层：**十个操作透镜**（怎么走流程）→ **七个认知框架**（怎么产生真正的新想法）→ **收敛与过滤**（怎么砍到 3–5 个）。

---

# 第一部分 · 十个透镜

用法：挑 2–3 个透镜走一遍，每个出 3–5 个候选，最后用第三部分的过滤器收敛。

## 透镜 1：问题优先还是方案优先

| 模式 | 起点 | 风险 |
|---|---|---|
| **问题优先** | 一个具体的失败 / 瓶颈 / 未满足需求 | 容易收敛成增量修补 |
| **方案优先** | 一个新工具 / 新洞见找应用 | "拿着锤子找钉子" |

**自检**：能说出一个具体的、正在受苦的人或系统吗？这个问题是真没解，还是只是没被营销？

**典型症状**：如果你开口就是"我们有 X 方法，可以试试用在 Y 上"，那是方案优先。把它改写成"Y 场景下有个失败，具体是…"，才算过了这一关。

## 透镜 2：抽象阶梯

| 方向 | 动作 | 产出类型 |
|---|---|---|
| **往上** | 把具体结果抬成一般原理 | 框架 / 理论论文 |
| **往下** | 把一般范式放到具体约束下测 | 实证 / 失败分析 |
| **往旁** | 同一抽象层换到邻域 | 交叉迁移 |

**自检**：往上一级，你能不能说出"任何满足 A 条件的策略，其上界都由 B 决定"这种形式的句子？往下加一个极端约束，它会不会崩？**崩掉的地方通常就是论文。**

## 透镜 3：张力与矛盾

突破常来自"两个大家都想要、但看起来冲突"的目标。

| 张力 | 研究机会 |
|---|---|
| 性能 ↔ 效率 | 少 10 倍算力能否匹配 SOTA |
| 安全 ↔ 可用 | 能否加约束而不牺牲能力 |
| 通用 ↔ 专用 | 什么时候微调真的赢过提示 |
| 准确 ↔ 可解释 | 机制洞见能否反过来改进架构 |
| 召回 ↔ 精确 | 代价不对称时最优点在哪 |
| 覆盖 ↔ 成本 | 多一分覆盖要花多少钱 |

**自检**：这个张力是真的（有文献分别优化两端），还是你自己假设的？你的"调和"在技术上可行，还是只是愿望？**如果只是"各让一步"，那是调参，不是新想法。**

## 透镜 4：交叉迁移

从别的学科借结构。**前提**：机制层面对得上，不只是表面像；不显然；能生成可检验预测。

| 来源领域 | 可迁移概念 |
|---|---|
| 可靠性工程 | 冗余设计的收益上限、失效相关性 |
| 金融 | 分散化极限、尾部相依、copula |
| 排队论 / 运筹 | 瓶颈、利特尔法则、资源分配的下界 |
| 统计物理 | 相变、临界现象、有限尺度标度 |
| 控制论 | 反馈、稳定性、鲁棒性边界 |
| 因果推断 | 识别性、混杂、可忽略性 |

**质量判据**：**结构映射**（机制能搬）还是**语言映射**（只是词像）？只有前者值钱。

## 透镜 5：什么变了（老问题在新条件下重开）

看什么变了：算力、规模、法规、工具、失败事件、用户行为。

**写法**：`X 之前不实用，因为 Y；但 Z 变了，所以现在值得重做。`

**自检**：你说的"变了"是可核验的事实（价格降了多少倍、规模到了什么量级、出现了什么新工具），还是模糊的时代感叹？

## 透镜 6：失败分析 / 边界探测

系统性地暴露一个被广泛使用的方法在什么条件下会崩。

**要探的边界**：分布（OOD）、规模（10×/0.1×）、对抗、组合、时间（概念漂移）、预算。

**自检**：是在探真边界（而不是重复已知局限）？能解释**为什么**崩，而不只是**崩了**？

## 透镜 7：简洁性检验

先问："更简单的做法够不够？"

**不必要的复杂度的信号**：

- 超参多，且最优区间窄
- 消融显示多数组件贡献微小
- 简单基线从没被认真调过
- 提升落在噪声里

**判据**：如果去掉一半组件后结果不变，那另一半不是深度，是掩饰。

## 透镜 8：利益相关者轮换

挨个坐进不同角色，每个坐 5 分钟，列出他前三个关切。

| 角色 | 核心问题 |
|---|---|
| 终端用户 | 好不好用？什么错误不可接受？ |
| 开发者 | 能否调试？维护成本？ |
| 理论家 | 为什么有效？有什么保证？ |
| 攻击者 | 怎么搞坏它？ |
| 伦理 / 合规 | 谁受损？是否可审计？ |
| 运维 | 成本多少？失效模式是什么？ |

**换视角常常直接换出可发表的问题**：从运维视角看，"再投入一个单位资源划算吗"；从合规视角看，"能否给出可承诺的上界"——后者就是统计证书类工作的位置。

## 透镜 9：组合与拆解

- **组合**：把两个互补的技术拼起来，问涌现出什么能力
- **拆解**：把一个庞杂的方法拆开，问哪个组件才是真正的瓶颈

**拆解的威力**：不是发明新东西，是把一个混在一起的东西分开，并证明其中某一部分贡献为零或为负。这本身就是很强的贡献。

## 透镜 10：两句话讲清

> **句 1（问题）**："[领域] 目前在处理 [具体问题] 上有困难，因为 [具体后果]。"
> **句 2（洞见）**："我们通过 [方法] 的 [关键机制] 来解决，它之所以有效是因为 [原因]。"

**写不出来的话**：回透镜 1（问题不清）、回透镜 7（洞见不清）、回透镜 3（意义不清）。

**自检**：外行同事能听懂为什么重要吗？去掉术语还成句吗？你能预判怀疑者的第一句反驳吗？

# 第二部分 · 七个认知框架

透镜是流程，框架是引擎。真正的新想法通常来自下面某一条。

## F1 双关联（Bisociation）

**原理**：新想法来自把两个**原本无关的参照系**连起来（Koestler, 1964）。不是同一框架内的联想，是跨框架的碰撞。

**操作**：选两个领域 → 各列 5–10 个核心概念 → 做交叉矩阵 → 逐格问"把 A 的概念用到 B 的问题上会怎样" → 筛出能生成可检验问题的组合。

**质量判据**：结构映射（机制能搬）还是语言映射（只是词像）？

## F2 问题重构（Representational Change）

**原理**：突破常来自**重新表述问题**，而不是解决问题。

| 策略 | 例子 |
|---|---|
| 改目标 | "让聚合更聪明" → "取消对聚合的依赖" |
| 改形式 | "硬阈值判定" → "潜变量识别问题" |
| 改粒度 | "整体指标" → "按阈值分层的指标曲线" |
| 改主体 | "模型该怎么答" → "输入该怎么设计" |
| 改时标 | "在线选择" → "部署前的预算分配" |
| 反向 | "如何提升 X" → "什么给 X 设了上界" |

**自检**：把当前问题句里的每个隐藏假设抽出来（形式、目标、粒度、主体、时标），逐个问"如果反过来呢"。

## F3 类比推理（Structure-Mapping）

**原理**：Gentner (1983) 的结构映射 + 对真实科学家的观察——**远距离的结构类比产生突破，近距离的表面类比只能修补**。

| 层级 | 描述 | 价值 |
|---|---|---|
| 表面 | 看起来像 | 低 |
| 关系 | 实体间关系对应 | 中 |
| **结构** | **深层因果机制对应** | **高** |

**操作**：

1. 用**纯关系语言**描述问题（剥掉领域名词）
2. 找其他领域解决同一关系结构的方法
3. 取最远且结构保真的那个
4. 映射机制 → 适配 → 生成可检验的预测

**验证清单**：机制映射对吗？能生成新预测吗？源领域的专家认可这个机制吗？

## F4 约束操纵

**原理**：Boden (2004) 区分三种创造力——**探索型**（在既定空间里搜）、**组合型**（把不同空间的元素拼）、**变革型**（改空间的规则本身）。**变革型最稀有、影响最大。**

**约束分三类**：硬约束（物理/逻辑必然）／软约束（惯例）／**隐藏约束（最肥沃）**。

**三种动作**：放松（"数据不必装进内存"→ 流式算法）／收紧（"预算必须更小"→ 效率研究）／替换。

**操作要点**：列出当前范式的 5–10 个约束，**标记哪些是隐藏的**（没人说过但大家都这么做）——那些就是变革型创造力的入口。

## F5 否定与反转（TRIZ）

**原理**：把领域内"人人都知道"的核心假设逐条否定，看能建出什么系统。

**操作**：列 5–10 条核心假设 → 逐条否定 → 筛掉不连贯的、筛掉已探索过的（除非条件变了）→ 留下"未探索且连贯"的。

| 假设 | 否定后 |
|---|---|
| 更多数据总能提升 | 收益在什么点饱和？饱和后的瓶颈是什么？ |
| 平均表现代表系统质量 | 最坏情况由谁承担？→ 换评价对象 |
| 更强的模型是更好的选择 | 强模型在什么条件下反而更差？ |
| 加一层能提升鲁棒性 | 这层的代价由谁承担？ |

## F6 使能因素扫描（邻近可能）

**原理**：创新发生在"当前可达边界"上。新想法在前提条件出现后才变得可想。

**操作**：列最近 1–3 年的**使能因素**（硬件 / 数据 / 工具 / 理论 / 监管）→ 逐个问"什么以前不可能、现在可能了" → 找多个使能的**交集** → 检查竞争（很多人能看到同一个机会时，速度或角度决定胜负）。

**时机判据**：

| 情况 | 判断 |
|---|---|
| 需要还不存在的技术 | 太早，搁置 |
| 五年前就能做 | 有人做了，去查文献 |
| **最近 6–18 个月才可行的** | **甜点区** |

## F7 两面神思维（Janusian）

**原理**：Rothenberg (1979) 发现顶尖创造者的共性——**同时持两个矛盾想法**，不选边，而是造出超越对立的新框架。

**操作**：找一个领域内的二元对立 → 拒绝选边 → 问"什么系统能同时得到 A 和 B"／"这个权衡在什么条件下不是根本的"／"这个对立是不是我形式化方式的产物"。

**关键判据**：综合是**新想法**，还是只是"各让一步"的折中？前者有框架变化，后者只是参数调平。

# 第三部分 · 收敛与过滤

## 收敛过滤器（把 10–20 个候选收到 3–5 个）

| 过滤 | 问题 | 淘汰条件 |
|---|---|---|
| 两句话 | 能讲清吗？ | 讲不清 → 淘汰 |
| 问题真实性 | 真有人因此受损吗？ | 没有 → 淘汰 |
| 简洁性 | 复杂度正当吗？ | 简单法够了 → 简化或淘汰 |
| 利益相关者 | 谁受益、谁会反对？ | 无明确受益者 → 淘汰 |
| 可行性 | 现有资源能做吗？ | 明显做不到 → 搁置 |
| 可证伪 | 什么结果会让你放弃？ | 说不出来 → 淘汰 |

## 选题阶段的七个常见坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 新而无用 | "没人做过 X"，但也没人需要 X | 透镜 1 |
| 默认增量 | 只是 +2% | 透镜 2 |
| 崇拜复杂 | 8 个组件各贡献一点 | 透镜 7 |
| 回音室 | 想法全来自同 10 篇论文 | 透镜 4 / F1 |
| 用过时的假设 | "这个试过不行"（5 年前） | 透镜 5 |
| 单一视角 | 只从工程师角度想 | 透镜 8 |
| 过早收敛 | 第一个想法就定了 | 走完发散阶段 |

## 一次深度构思的四阶段（约 90 分钟）

| 阶段 | 时间 | 做什么 |
|---|---|---|
| 1 测绘 | 15 min | F4 列出范式约束（标硬/软/隐藏）；F6 列出使能因素 |
| 2 制造扰动 | 30 min | F5 否定 3 个软/隐藏约束；F1 选一个远域做交叉矩阵；F2 用三种方式重述问题 |
| 3 深化 | 30 min | F3 给每个候选找结构类比并抽预测；透镜 2 上下各走一级；F7 找张力并尝试综合 |
| 4 评估 | 15 min | 两句话测试 → 收敛过滤器 → 留下 3–5 个 |

## 卡住时查这张表

| 症状 | 用哪个 |
|---|---|
| 只会从同一个角度想 | F2 问题重构 |
| 想法全来自同一个子领域 | F1 双关联 / F3 类比 |
| 觉得想法"太怪"先自我否定 | F5 否定（怪才是要点，先发散） |
| 每个想法都只是 +2% | F4 约束操纵 |
| 选项太多定不下来 | 透镜 5 / F6 使能因素（现在可行的是什么） |
| 卡在两个方案间 | F7 两面神（找综合） |

## 一条元原则

**先发散，后评估。** 候选列表要**手写下来，包括被否掉的**——被否掉的方向不是浪费，是原材料：它留下了可复用的数据、脚本、以及对竞争工作的核对。很多好选题是从一个被否掉的方案里长出来的。
