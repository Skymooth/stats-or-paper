# 全文骨架与各节职责

先定骨架，再写句子。这一份管"整篇怎么搭"，段落内部的问题见 `paragraphs.md`，句子与用词见 `style.md`。

---

## 一、先定一句话论点

整篇论文应当围绕一个可陈述、可检验的主张组织：

> **方法 X 在设定 Z 下，对任务 Y 的指标 M 优于现有做法。**

- 引言**陈述**它
- 方法**解释**它怎么做到
- 实验**证明**它

把这句话填出来（X / Y / Z / M 各是什么），写成一段，放到引言第三段。如果读起来不像这篇论文的核心，说明你还没想清——回到 `paragraphs.md` §一 重来。

**常见失败**：X 写成"我们提出了一个框架"（这不是主张，是动作）；Z 写成"在大模型时代"（这不是设定，是时代背景）。

## 二、页面预算（按 10 页正文制换算）

| 章节 | 占比 | 页数 | 作用 |
|---|---|---|---|
| 摘要 | ~2% | 0.2 | 5 句，必须有数字 |
| 引言 | 13–17% | 1.5–2 | 问题 → 差距 → 洞见 → 贡献 |
| 背景与动机 | 8–12% | 1 | 术语 + 关键观察 |
| 方法 / 设计 | 25–33% | 3 | 架构 → 逐模块 → 备选与权衡 |
| 实现 | 4–8% | 0.5 | 原型、代码量、关键工程决策 |
| 实验 | 25–33% | 3 | 设置 → 端到端 → 消融 → 扩展性 |
| 相关工作 | 8% | 0.8 | 按路线分组 + 差距矩阵 |
| 结论 | 4% | 0.4 | 三句话 |
| 局限 | — | 0.3 | 必写 |

**最常见病**：方法写太长、实验写太短。**把方法压到 1/3 以内，把实验撑到 1/3。**

## 三、引言四段结构

### 段 1 · 问题（~0.5 页）

建立领域与重要性，**用具体数字**（规模、负载、延迟要求、错误代价），不要用"随着 X 的快速发展"开头——那句话能安到任何一篇论文前面。

三种开法，按你的任务成熟度选：

| 开法 | 适用 | 结构 |
|---|---|---|
| A · 先定义任务 | 任务小众 | 一句话定义（从什么输入得到什么输出）→ 2–3 个代表场景 |
| B · 先讲应用 | 任务已普及 | 应用重要性 → 由此提出的精度/成本/可靠性要求 |
| C · 从一般到具体（推荐） | 设定较新 | 一般任务 → 本文的具体设定 → 明确输入/输出与边界 |

### 段 2 · 差距（~0.5 页）

列举具体差距 **G1–Gn**，每条一句话 + 证据，且**每条后面都要有对应答案**，形成与读者的契约。

这是全篇最容易失分的地方：**只写"现有方法效果不好"是废话，必须写技术原因**——为什么它在这个指标上**必然**不行。

三种写法：

**写法 1（已有任务、有现成方法）**

```
一般挑战 → 传统方法的局限 → 近期方法 1 的局限（给原因）→ 近期方法 2 的局限（给原因）
→ 最后这个局限正好是你解决的
```

**写法 2（你的洞见有历史根源）**

```
主流方法的局限 → 一条经典线索其实已含相似洞见 → 但经典线索仍不够（为何不够）
→ 回到现代方法的技术原因 → 自然过渡到你的方法
```

**写法 3（新任务，无直接方法）**

```
我们的目标是 X。这个问题难在三处。
First, …（可观测局限 + 技术原因）
Second, …
Finally, …
→ 过渡到我们的方案
```

### 段 3 · 核心洞见（1 段）

用 §一 的论点公式，一句话说清"为什么我们的方法能解决"。**不要在这里铺术语**，先给机制，再给它一个名字。

### 段 4 · 贡献（~0.5 页）

编号列表 3–5 条。**每条贡献可检验，且能映射到某一节。**

> **自检**：把贡献列表逐条遮住，看能否在正文找到对应的小节标题。找不到的那条，要么补实验，要么删。

## 四、方法节：架构先行，逐模块，讲备选

1. **架构总览**（~0.5 页）：**先画图**，再用一段文字走查主要组件与数据流。
2. **逐模块设计**（~2 页）：每个模块讲四件事——它做什么、做了什么设计选择、**考虑过哪些备选**、为什么选这个。
3. **设计备选与权衡**（~0.5 页）：对每个重大决策，显式讨论没选的那个及原因。

**判定**：如果方法节只有"我们采用了 X"，没有"我们也考虑过 Y，但它会导致…，所以选 X"，审稿人会认为你没做设计，只是拼装。

---

## 五、实验节：每个结论说三遍

**这是最容易被忽略、也最能救论文的一条。**

| 位置 | 写什么 |
|---|---|
| 小节开头（假设） | "我们预期 X 优于 Y，因为…" |
| 小节结尾（结论） | "结果显示 X 比 Y 高 Z 个百分点（95% CI […]）" |
| 图注（证据） | "图 N：X 与 Y 在 3 个数据集上的对比，误差棒为 95% bootstrap 区间" |

**原因**：审稿人是跳读的。三处重复保证他在任何一处都拿到结论。

### 两类实验

| 类型 | 做什么 |
|---|---|
| 端到端对比 | 你的方法 vs 强基线，在主指标上、于目标环境 |
| 消融 | 逐个移除组件，测各自贡献 |

### 实验节四段

1. **设置**（~0.5 页）：硬件/数据/基线/指标，足以复现
2. **主结果**（~1–1.5 页）：端到端对比
3. **消融 / 微基准**（~1–1.5 页）：隔离每个设计决策
4. **扩展性 / 敏感性**（~0.5 页）：随规模、预算、超参变化

图表规格见 `reporting.md` §二–§三；基线、消融、上限对照的完整性见 `rigor.md` §二。

## 六、摘要与标题

**标题**：写进"对象 + 动作 + 关键限定"。不要用 "Towards…" "A Study of…" "An Empirical Investigation into…" 这类空壳。

**摘要**：五句式，100–180 词，正文最后写。句式模板见 `style.md` §五。

**硬要求**：摘要里必须至少有一个带区间的数字，且这个数字在正文、表、图中四处一致。

---

## 七、相关工作：按路线分组，给差距矩阵

- 按**方法路线**分组，不按论文逐条。
- 每组讲三件事：他们做什么 → 剩下什么局限 → 你怎么不同。
- 对比 4 个以上系统时，**用表**。
- **慷慨引用**——审稿人很可能就是相关论文的作者。

差距矩阵模板：

| 工作 | 正式/预印 | 做了什么 | 没做什么 | 我们补什么 |
|---|---|---|---|---|
| A et al. | 正式（会议'YY） | 测量了… | 未处理… | 我们给出… |
| B et al. | 预印 | 提出… | 未覆盖… | — |

> **规则**：矩阵里"没做什么"那一列，每一行都必须能对应到你贡献里的一条，否则那一行是凑数，删掉。

三种致病写法：流水账 / 只褒不贬 / 缺差距矩阵。详见 `evidence.md` §三–§四。

---

## 八、结论与局限

**结论只用三句**：① 提的问题是什么 ② 解决思路是什么 ③ 关键结果是什么。不引入新结果，不写成执行摘要。

**局限必写**，且要具体、可验证、指向未来工作。写法见 `rigor.md` §五。

## 九、四种写作模式（挑一个贯穿全文）

| 模式 | 结构 | 何时用 |
|---|---|---|
| **差距分析型** | 引言列 G1–Gn → 设计给 A1–An | 现有系统有明显缺陷 |
| **观察驱动型** | 动机列 O1–O3（真实数据）→ 从中推设计 | 有真实测量数据 |
| **贡献列表型** | 引言编号贡献，各自映射一节 | 贡献相对独立 |
| **论点公式型** | 全文围绕 §一 那句话 | 有单一核心主张 |

可以混用两种（如"差距分析 + 论点公式"），但**不要四种都用**——那意味着你其实没有主张。

## 十、投稿前七阶段检查

| 阶段 | 检查 |
|---|---|
| 1 结构 | 论点公式在不在？贡献 3–5 条？每条映射到节？ |
| 2 写作质量 | 读者七预期过了吗？术语一致吗？（`style.md`） |
| 3 实验严谨 | 每个结论说三遍了吗？消融齐全？有方差？（`rigor.md`） |
| 4 设计质量 | 每个大决策讨论了备选？ |
| 5 学术诚信 | 引用全部程序化核验？无编造数据？（`evidence.md`） |
| 6 场所要求 | 页数、盲审、必填章节（局限 / 影响声明 / 复现清单） |
| 7 最终通读 | 数字四处一致？图表自足？参考文献无占位符？ |
