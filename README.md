# stats-or-paper

一套面向 **统计 / 运筹 / 机器学习系统** 方向的论文写作、审稿与自查方法。

不是"写作风格指南"，而是一套**防审稿人翻车**的检查制度：每个 claim 有证据等级、每个数字带区间、每条引用可点开核实、每个假设被显式交代。

纯 Markdown，零可执行代码，不发任何网络请求。

---

## 它解决什么问题

论文被拒，很少是因为"写得不好看"，多半是因为：

- 证据撑不住 claim（用了"全面领先""所有模型"这类全称量词，实验只覆盖 3 个设定）
- 数字没有不确定性（只报点估计，样本 99 却当 9900 用）
- 引用是编的或引错了（文章存在，但没说过这句话）
- 关键假设没说（审稿人一算就发现结论依赖一个未声明的条件）
- 相关工作只褒不贬，且没做差距矩阵
- 实验缺消融、缺上限对照、基线没同预算调参

这套文件把上述每一项变成一条可执行的检查，并给出**改法**，而不只是判定。

**完全不用 agent 也行**：`references/review.md` 的三视角清单和 `references/rigor-rubric.md` 的六维打分，人工逐条过一遍就有用。

## 设计原则

1. **证据优先于表达。** 每个事实性 claim 都要能标出证据状态（正式 / 预印 / 自算 / 推断）。标不出来，就说明它不该以现在的强度出现。
2. **可执行优先于正确。** "要诚实""要严谨"是废话；"每个数字有对应运行日志吗、有没有可疑地圆整的数"才是检查。
3. **症状路由，按需加载。** 一份 10 万字的写作手册没人读得完，也没必要。SKILL.md 只留路由表。
4. **把别人的边界说清楚。** 相关工作不是罗列，是差距矩阵：每行"没做什么"必须能落到你的一条贡献，否则那行是凑数。
5. **失败痕迹是好东西。** 诚实的探索轨迹（试过什么、为什么放弃）比平顺的成功叙事更可信——写进引言或附录。

## 它不做什么

- 不生成文献、不代查文献。引用核验要靠你自己的检索工具与数据库。
- 不替你跑实验、不生成数据。
- 不保证录用。它降低的是"可避免的失分"。
- 不是领域知识库。统计/OR/ML 之外的方法论（如临床试验报告规范、法学论证）只在 `evidence.md` 里给了指针。

## 安全

- **零可执行代码**：全部是 Markdown，没有脚本、没有安装器、没有 hooks。
- **不发网络请求**：不会把稿件、数据或任何内容送出本机。
- **不写文件**：它只提供方法，是否落盘由使用它的 agent 与你的授权决定。

如果你的 agent 环境默认允许联网或执行代码，那是**该环境**的配置，不是本 skill 的行为。

## 维护

发现某条建议在你的实际投稿中被审稿人反驳过 → 直接改对应文件，并在该条后面加一行：

```html
<!-- 案例：某次会议中被质疑，已调整为…… -->
```

这类实战记录比任何写作理论都值钱。改动请更新 [CHANGELOG.md](CHANGELOG.md)，并在 PR 里说明你遇到的真实场景。
